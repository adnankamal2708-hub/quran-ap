# Quran map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** All 604 Mushaf pages as a grid shaded by how much of each page the learner understands, opening into a page view with known words lit.

**Architecture:** A build script tags every Quran word with its occurrence-index key (the matcher behind "% of the Quran") and writes it with Tanzil's page starts to a lazy-loaded data file. A pure module turns mastered words into page shares and per-word flags; a UI module draws the map and page view on the Quran tab.

**Tech Stack:** Vanilla JS (ES5 style, like the rest of js/), Node build scripts, node test files, Playwright e2e.

**Spec:** docs/superpowers/specs/2026-11-17-quran-map-design.md

## Global Constraints

- Files under 300 lines; new files added to build-files.js (data files load lazily, not in the bundle).
- A word is known exactly when it counts toward the "% of the Quran" figure: its key, `OCCURRENCE_INDEX_KEY(word.arabic)` for a canonical word with SRS stage ≥ 2.
- No change to progress, SRS or Firestore; the map only reads.
- All text through `t()` in js/i18n/strings-en.js; Arabic elements carry `lang="ar" dir="rtl"`.
- Page data: Tanzil Quran Metadata 1.0, CC BY 3.0, credited in Profile → About.
- PWA: the data file is precached by sw.js; the map works offline once opened.
- No XP, points or leaderboards.

## Review Focus

- A page starting mid-surah and ending in the next surah (e.g. page 2–3 boundaries, page 604 holding 112–114): every ayah appears on exactly one page.
- A learner with no mastered words: map shows all pages at step 0, no errors, and the copy still reads well.
- Map vs Home: the summed known tokens over all pages equal the tokens behind `getRealWordsCoveragePercent` for the same words.
- The data file fails to load (offline, first open): the card says so and offers a retry, nothing breaks.
- Word joining: tokens are split on whitespace like the occurrence index, not joined like `dailyAyahWords`, so per-ayah token counts match the index.
